## Введение
Вас добавляют в группу Telegram. В чате появляется ссылка. Вы нажимаете на нее — и ваш аккаунт Telegram перестает быть только вашим.

Как это происходит?
Telegram Desktop передает нажатые ссылки уже запущенному экземпляру программы через локальный сокет в виде текста, не экранируя при этом символ, используемый для разделения команд. В результате специально сформированная ссылка воспринимается не как одна инструкция, а как несколько.

Обнаруженная мной цепочка уязвимостей состоит из двух изъянов. Первый — это сама возможность инъекции. Второй связан с тем, на что воздействует внедренная команда: это внутренняя схема URI `interpret:`, которая считывает файл, указанный в инструкции, и отправляет его в чат без проверки инициатора запроса и без подтверждения со стороны пользователя. В совокупности эти уязвимости позволяют через нажатие ссылки организовать чтение произвольных файлов. В этой статье я подробно разберу данную цепочку и продемонстрирую, как с ее помощью можно украсть файлы, содержащие данные для входа в аккаунт жертвы.

## Одна ссылка — два процесса

Операционные системы позволяют программам регистрировать схемы URI, чтобы знать, какое приложение запустить при обнаружении ссылки такого типа. Telegram Desktop регистрирует схему `tg`. С этого момента система «знает», что ссылка вида `tg://...` относится к Telegram, и запускает его, передавая URL в качестве аргумента командной строки.

Если Telegram еще не запущен, процесс стартует, принимает строку как параметр, преобразует ее в объект URL и обрабатывает внутри себя: работает один процесс, и никакого межпроцессного взаимодействия не требуется.

Но что, если Telegram уже запущен? Операционная система этого не знает и не проверяет: она в любом случае запускает новый процесс, идентичный первому. Telegram должен сам определить, что он является «лишним» экземпляром; это делается путем попытки подключения к локальному сокету.

Уже запущенный экземпляр выступает в роли сервера: он прослушивает этот сокет с момента своего запуска. Новый процесс выступает в роли клиента. Если ему удается подключиться, значит, другой экземпляр уже активен; тогда новый процесс передает ему ссылку и завершает работу.

Сокет не передает объекты — он передает байты. Объект URL, хранящийся в памяти нового процесса,
не может быть передан через этот канал напрямую, поэтому его приходится преобразовывать в текстовую строку.

У этой операции есть название: сериализация. Обратный процесс — восстановление объекта из текста —
называется десериализацией. Оба действия неизбежны при передаче структурированных данных через границы;
именно в этот момент границы внутри данных перестают поддерживаться структурой и превращаются
в символы текста.

Telegram использует для этого собственный простой формат. Каждая команда состоит из ключевого слова,
аргумента и завершающей точки с запятой. Ссылка для открытия преобразуется в такой вид:

```text
OPEN:tg://x?a=1;
```

Адрес `tg://x?a=1` не соответствует ни одному обработчику внутри Telegram, поэтому сама по себе эта ссылка
ничего не делает. Она служит лишь средством передачи данных.

Эта строка формируется следующим образом (по одной на каждый URL, который нужно открыть):

```cpp
// sandbox.cpp:295-297
for (const auto &url : cRefStartUrls()) {
commands += u"OPEN:"_q + url.toString(QUrl::FullyEncoded) + ';';
}
```

На другой стороне запущенный экземпляр выполняет десериализацию: он считывает полученные байты,
разбивает их по символу точки с запятой и воспринимает каждый фрагмент как отдельную команду.
Для каждого фрагмента, начинающегося с `OPEN:`, программа берет последующую часть и восстанавливает
из нее URL — точно так же, как если бы он был передан через командную строку.

## Неэкранированный разделитель

Что же произойдет, если одно из передаваемых значений само по себе содержит точку с запятой — тот самый символ, который используется в формате как разделитель? Возьмем уже знакомую нам ссылку и добавим к ней кое-что еще:

```text
tg://x?a=1;CMD:quit
```

Новый процесс воспринимает эту строку как единый URL, поскольку для него данная точка с запятой — лишь обычный символ внутри строки запроса. Процесс преобразует строку в плоский формат и записывает её в сокет:

```text
OPEN:tg://x?a=1;CMD:quit;
```

Запущенный экземпляр приложения разбивает строку по каждой точке с запятой и получает на выходе две инструкции.
